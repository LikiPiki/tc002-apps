# Локальная разработка

## Команды

Из корня репозитория:

| Команда | Назначение |
| --- | --- |
| `make help` | Список основных команд |
| `make check` | Проверка форматирования Go, vet, тесты |
| `make build` | Нативные Go-бинарники в `bin/` |
| `make docker-build` | Сборка production-образов Go |
| `make dev` | Сборка и запуск виртуального AWTRIX |
| `make dev-notify TEXT="Привет!"` | Уведомление из Go-контейнера |
| `make dev-check` | Запуск AWTRIX, воркера и HTTP smoke-проверки |
| `make dev-logs` | Логи AWTRIX |
| `make dev-down` | Остановка окружения без удаления данных |

Для Go-проверок требуется Go 1.24+. Для dev-окружения достаточно Docker с Compose v2, поддерживающим `up --wait`.

## Виртуальные часы

```sh
make dev-check
```

Первая сборка скачивает закреплённую версию исходников AWTRIX NG и зависимости, затем компилирует C++-движок. Это существенно дольше сборки наших Go-команд. Повторные запуски используют Docker cache.

Откройте **http://localhost:8080**: live preview показывает экран 52 × 16, как у TC002. Уведомление smoke-проверки может уже исчезнуть к моменту открытия; отправьте новое:

```sh
make dev-notify TEXT="Hello TC002"
```

Можно запустить Go-клиент непосредственно на компьютере:

```sh
AWTRIX_URL=http://localhost:8080 go run ./cmd/clockctl --text 'Native Go works'
```

Вкладка Scripts позволяет вручную загрузить Berry-приложения из `apps/`, проверить отрисовку и ошибки выполнения. Автозагрузки скриптов пока нет.

## Что проверяет dev-check

- Настоящий headless-движок AWTRIX запускается и отвечает на HTTP.
- Наш воркер собирается и выполняет один цикл (пока это заглушка).
- Наш Go-клиент отправляет уведомление в реальный HTTP API; ошибка или не-2xx ответ завершают проверку с ошибкой.

Это smoke-проверка интеграции, а не автоматическая проверка изображения: итоговую отрисовку смотрим в браузере. Для конкретных обработчиков добавляем unit-тесты данных, для Berry — отдельные сценарии.

Датчики, физические кнопки, Bluetooth, звук и производительность TC002 здесь не эмулируются.

## Данные и сеть

Настройки, Berry-скрипты и ресурсы сохраняются в Docker volume `tc002-dev_awtrix-data`. `make dev-down` его сохраняет. Для полного сброса локальных часов (включая скрипты и настройки):

```sh
docker compose -p tc002-dev -f dev/compose.yaml down -v
```

В контейнере используется `--lan`, чтобы API был доступен соседним сервисам. На компьютере порт опубликован только на `127.0.0.1`. Окружение отдельное от production Compose и не обращается к физическим часам или VPS.

Не включайте авторизацию в этом dev-инстансе: текущий `clockctl` рассчитан на API без неё. Если включили её случайно, отключите в веб-интерфейсе или сбросьте dev volume.

## Версия AWTRIX

Commit upstream закреплён в `dev/Dockerfile.awtrix` через `AWTRIX_REV`. При обновлении меняем SHA и повторяем `make dev-check`. Перед загрузкой приложений на устройство сверяем совместимость с установленной на часах версией AWTRIX.
